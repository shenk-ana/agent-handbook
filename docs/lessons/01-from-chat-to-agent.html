从聊天到 Agent
会说的 AI 和会做的 AI

你问 AI“周末带爸妈去哪吃饭”，它给你列了一堆建议，最后加一句“建议您自行查询”。你想：要是它能自己去查一下就好了。能自己去查、自己核对、把事办完的 AI，就叫 Agent。

⏱ 约 15 分钟 👤 所有人；原理层面向开发者 🎬 2 个交互演示

学完这一课，你能

  • 说出聊天机器人和 Agent 的三个区别
  • 认出 Claude 应用里哪些时候是在“动手”，而不只是“说话”
  • 判断一件事用普通聊天就够，还是值得交给 Agent
  • （开发者）理解“同一个模型，接上工具和循环就成了 Agent”，以及它在 API 和 Claude Code 里的样子

一句话总结

聊天机器人只会“说”；Agent 会“做”：它能用工具去查、去改、去执行，分好几步完成任务，并根据每一步的结果调整下一步。

01同一个任务，两种做法

先看同一个任务的两段演示。任务是：“下周六想带爸妈去湖边吃午饭，帮我挑一家合适的餐厅，把理由整理成一张表。”

第一段，Claude 手里没有任何工具，只能聊天。留意右边的循环图：它一直没有转起来。

第二段，同一个任务，Claude 可以用“网页搜索”。这次注意循环图怎么转：想一下，查一下，看结果，再想。

💡
比一比，谁在跑腿

第一段里，打开网页、挑候选、复制粘贴、打电话确认，都是你在做，Claude 只负责“读和写”。第二段里，这些事 Claude 自己做了，你只说了一句话。演示里的餐厅和网址都是虚构的。

02三个区别

从聊天机器人到 Agent，差别可以归成三点：

聊天机器人Agent
会不会动手只能根据已经知道的内容写回答能用工具：搜索网页、读文件、运行代码、操作软件
会不会多步你问一句，它答一句自己把任务拆成几步，一步接一步做下去
会不会根据结果调整答完就结束，对错要你自己判断看了结果再决定下一步：没查到就换个关键词，查到矛盾就再核对
🧩
打个比方：顾问和助理

聊天机器人像一位电话顾问：知识丰富，你问什么都能说上几句，但他不会离开电话去替你办事。Agent 像一位助理：你说“帮我订个餐厅”，他会自己去查、去比较、打电话确认，回来告诉你“订好了，周六 11 点，靠窗”。后面的课会一直请这位“新助理”出场。

第三点最容易被忽略，也最关键。演示 B 里，Claude 第一次搜索之后发现“还不知道周六营不营业”，于是又搜了一次。这种“看结果、再调整”的能力，让 Agent 能处理没法事先规划好的任务。

03Agent 是怎么“动手”的

Claude 的“大脑”是一个大语言模型。它本身只会读文字、写文字。所谓“动手”，是它写出一张格式严格的“单子”，比如“用网页搜索，关键词是……”，由外面的程序照着执行，再把结果交还给它。这张单子叫工具调用。

所以，一个 Agent 至少由三样东西组成：做决定的模型、负责执行的工具，以及把两者串起来、一圈一圈转的循环。第 15 课会专门拆开这个循环。

在 Claude 应用里（网页、电脑或手机），你其实已经能看到不少“动手”的时刻。截至 2026-11，常见的有：

  • 网页搜索：查最新信息，回答里带着来源链接，你可以点过去核对。
  • 读你给的文件和图片：上传 PDF、Word、表格或者拍一张照片，它能读懂里面的内容，包括图表。
  • 做出文件：Claude 可以在一个和你电脑隔开的临时空间里写代码、算数据，直接做出 Excel、PPT、Word 或 PDF 文件给你下载。这个功能叫“创建和编辑文件”（Create and edit files，以界面为准），个人套餐默认开启，也可以在设置里关闭。

此外，它还能把一份文档、一个小网页工具这样的成果单独放在对话旁边，方便修改和分享（第 8 课）；也能接上你的日历、网盘等服务（第 6 课）。你在界面上看到“正在搜索……”“正在运行代码……”之类的提示，就是循环在转。还有一些更进一步的产品形态，第 3 课会一起介绍。

⚠️
功能和套餐会变

上面这些功能，有的所有人都能用，有的需要付费套餐，团队版还可能要管理员先开启。是否可用，以你账号里的设置和官方帮助中心为准。

原理层从 API 看：区别就在 tools 和循环▾

切到两段演示的“API 视角”对比一下：

  • 只聊天：请求里没有 tools 字段。模型每次只返回 text 内容块，stop_reason 都是 end_turn。一来一回，没有循环。
  • Agent：请求里声明了工具。模型可以返回工具调用，执行结果再交还给模型，如此往复，直到它不再调用工具。

演示 B 用的网页搜索是一种服务端工具：由 Anthropic 的服务器替你执行。所以 server_tool_use（发起搜索）和 web_search_tool_result（搜索结果）出现在同一条 assistant 消息里，最终回答的文字块带着 citations。你自己定义的工具（比如查数据库）则是客户端工具：模型返回 tool_use 并以 stop_reason: "tool_use" 停下，由你的程序执行后用 tool_result 回传。第 15 课的天气演示就是这一种，第 17 课会详细对比两者。

模型还是同一个模型。是否“成为 Agent”，取决于外面有没有给它工具、有没有一个循环去执行它开出的单子。

04聊天还有用吗？

当然有。不是每件事都需要 Agent。判断方法很简单：这件事需不需要 Claude 去“外面”拿东西，或者去“外面”改东西？

普通聊天就够值得让它动手
改一段你已经写好的文字查最新的价格、新闻、营业时间
解释一个概念、出一个点子读一份 80 页的合同，找出风险条款
翻译你贴进来的一段话把一份数据表算出结果，做成图表和文件
帮你想一封邮件怎么写核对一件事的多个来源，给出处

左边这些，所需的信息你已经给了，Claude 的知识也够用。右边这些，要么需要最新信息，要么需要处理大量材料，要么需要真的“做出”一个东西。让它动手，你省下的是跑腿的时间。

动手也意味着风险：它可能查错、改错、点错。所以好的 Agent 在做有影响的事之前会停下来问你。第 2 课讲它的能力边界，第 9 课讲安全。

原理层在 Claude Code 里看同一件事▾

如果你用 Claude Code，“聊天”和“Agent”的差别每天都在眼前：

  • 问它“Python 的列表推导式怎么写”，它通常直接回答，不调用工具。这时它就是一个聊天机器人。
  • 问它“这个项目的测试为什么挂了”，它会调用 Bash 跑测试、用 Read 读文件、用 Edit 改代码，再跑一遍测试确认。终端里每一行 ⏺ 工具名(参数) 就是一次工具调用。

模型并没有换，换的是任务：后一个问题的答案不在模型脑子里，而在你的代码库里。Claude Code 给模型配好了读写文件、执行命令、搜索的工具和权限检查，所以它能自己去拿。第 15 课的“修测试”演示完整展示了这个过程。

05动手试一试

🔍 同一个问题，开关搜索各问一次 不需要写代码

在 Claude 应用里，用两个新对话问同一个问题：一次让它别上网，一次请它上网查。

请不要上网搜索，只根据你已经知道的内容回答：我所在的城市这个周末有什么值得去的展览？
请上网搜索后回答：我所在的城市这个周末有什么值得去的展览？每一条都告诉我来源。
  1. 把“我所在的城市”换成你住的城市。
  2. 对比两次的回答：哪一次说了“我无法确认”？哪一次带了来源链接？
  3. 点开一个来源，核对它说的日期和地点对不对。

提示：网页搜索的开关位置会随版本变化，有的界面会在需要时自动搜索。如果它仍然说无法上网，可能是账号没开网页搜索：去设置里找“网页搜索”（界面上可能显示为 Web search，以界面为准）。团队账号可能需要管理员先开启。

06常见误区

✗

Agent 是一个比聊天机器人更聪明的新模型。

✓

模型可以是同一个。区别在于有没有给它工具，以及有没有一个循环让它“做一步、看一步”。

✗

能用工具，就什么都该交给 Agent。

✓

改写、解释、出点子这类事，普通聊天又快又好。需要外部信息或者要真的做出东西时，才值得让它动手。

✗

Agent 查过资料，结果就一定对。

✓

查资料能减少错误，但网页本身可能过时或出错。看它给的来源，重要的事自己再核对一次。

07小测验

Q1下面哪个最能说明 Claude 正在“像 Agent 一样”工作？
动手（用工具）、多步、根据结果调整，三点都占了。回答长短和用词与是不是 Agent 无关。
Q2哪件事用普通聊天就足够了？
改写你已经给出的文字，不需要外部信息，也不需要做出文件。A 需要实时信息，B 需要读大量材料并生成结果。
Q3（开发者）在 API 层面，“只聊天”和“Agent”的请求最关键的区别是？
同一个模型就能做 Agent。关键是 tools 字段和外层循环（或者服务端工具在服务器上完成的循环）。

08推荐工具与延伸
