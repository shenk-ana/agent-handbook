能力边界与幻觉
它擅长什么，又会在哪里出错

Claude 能在几秒钟里读完一份长报告，也可能把报告里的一个数字说错，而且说得很笃定。知道它的长处和短处，你才知道哪些事可以放心交给它，哪些事必须自己再看一眼。

⏱ 约 15 分钟 👤 所有人；原理层面向开发者 🎬 1 个交互演示 · 1 个小练习

学完这一课，你能

  • 说出 Agent 擅长和不擅长的几类事
  • 解释什么是幻觉、什么是知识截止日期
  • 用几个简单的办法核对 Claude 的回答
  • 判断一件事该不该交给 Agent
  • （开发者）在 Claude Code 里用“先读再答”和“跑测试验证”减少幻觉

一句话总结

Claude 擅长读、写、整理和推理，但它的知识有截止日期，也会“一本正经地说错”；让它查证、给出处，并按“出错代价”和“能否核对”来决定交给它多少。

01它擅长什么，不擅长什么

先看一个例子。你请 Claude 总结一份 40 页的市场报告，它几秒钟就给出了五条清晰的要点，结构比你自己整理的还好。可其中一条写着“线上销售占比 38%”，原文其实是“线下 38%、线上 62%”：它把两个数字记反了。读得快、写得好，和偶尔记错细节，常常同时出现。

再给一张粗略的地图。左边是 Claude 一般做得好的事，右边是要多加小心的事：

通常做得好要多加小心
读长文、提炼要点、改写和翻译精确的数字、日期、人名，尤其是凭记忆说出来的
按你的要求起草邮件、报告、方案最近发生的事、会变化的信息（价格、政策、营业时间）
出点子、列选项、比较优缺点需要专业资质判断的事：医疗、法律、投资
按步骤推理、写代码并运行检查你没告诉它、它也查不到的情况（你的家庭、公司内部规定）
用工具查资料、核对多个来源做了就收不回的操作：发出去的消息、付掉的钱

注意右边第四行：Claude 不会读心。它不知道的事，它要么问你，要么只能猜。第 4 课会讲怎么把这些信息交代清楚。

02幻觉：一本正经地说错

AI 有时会编造内容，而且语气和说真话时一模一样。这种现象叫幻觉。常见的样子有：

  • 编出一本不存在的书、一篇不存在的论文，作者和年份都像模像样；
  • 把一个数字记错，比如把 2.8% 说成 8.2%；
  • 说某个软件“有这个按钮”，其实没有，或者是旧版本才有；
  • 在 Agent 任务里，工具其实报错了，它却当作成功继续往下做。
🧩
打个比方：记性很好但爱“补全”的朋友

你问一位博览群书的朋友某句名言出自哪里。他记得大意，却记不清出处，于是顺口说了一个“听起来很对”的人名。他不是故意骗你，只是习惯把话说圆。Claude 的幻觉有点像这样。

最新的模型比早期的模型少犯这种错，也更愿意说“我不确定”。但幻觉没有被消灭，只是变少了。越是冷门、越是精确、越是新近的信息，越要留个心眼。

原理层幻觉从哪里来▾

大语言模型的基本工作方式，是根据前文一个接一个地生成最可能的下一个 token。“可能”不等于“真实”：当模型对某个事实只有模糊印象时，它仍然能生成一段流畅、格式正确的文字，这段文字可能和事实不符。

几个会加重幻觉的因素：

  • 训练数据里很少出现：冷门的人名、小众软件的具体参数。
  • 需要逐字精确：引用原文、版本号、法律条文编号。
  • 超出知识截止日期：模型只能用旧信息去“推断”新情况。
  • 上下文里缺少依据：没有给它材料，也没让它去查。

缓解的思路是让回答“有据可查”：把材料放进上下文（上传文件、项目知识）、让它用工具检索并引用来源、让它运行代码或测试来验证。这些方法能显著减少幻觉，但都不能保证零错误，所以重要结论仍然需要人来把关。第 20 课讲怎么用评测系统地衡量它。

03知识截止日期

Claude 的知识来自训练时读过的资料。这些资料收集到某一天为止，这一天就是它的知识截止日期。截至 2026-11，Anthropic 公布的当前 Claude 模型，可靠知识截止于 2026 年 6 月。

这意味着：2026 年 6 月以后的新闻、价格调整、新产品，Claude 本身不知道。如果它没有搜索工具，又被问到这些事，它最好的做法是告诉你“我的信息可能过时”。最糟的做法，是用旧信息给你一个看起来很确定的答案。

04为什么要验证，怎么验证

验证不是不信任 Claude，而是把它当成一位能干但会出错的同事。重要的东西，谁写的都要过一遍。几个简单好用的办法：

  1. 要出处：请它“每一条都附上来源”。打开网页搜索时，回答里会带来源链接，点开看看原文是不是这么说的。
  2. 给材料：与其让它凭记忆回答，不如把合同、说明书、表格直接上传给它，让它“只根据这份文件回答”。
  3. 问把握：问一句“哪些地方你不太确定？”它通常会指出自己没把握的部分。
  4. 抽查：长篇总结不必逐字核对，挑两三处关键数字回原文找一找。
  5. 换个问法：同一个关键事实，换个角度再问一次，看说法是否一致。

验证要花多少力气，取决于出错的代价。给朋友的生日祝福写错一个词，无伤大雅；写进合同里的金额写错一位，后果就严重了。

原理层在 Claude Code 里减少幻觉▾

编程场景有一个巨大的优势：很多结论可以自动验证。用好这一点，幻觉就很难溜过去：

  • 先读再答：问到具体代码时，要求它先打开相关文件再回答，不要凭文件名猜测实现。Anthropic 的提示词最佳实践里，专门给出了“回答前先调查”这类指令写法。
  • 把验证写进完成标准：例如“改完后运行 npm test，全部通过才算完成”。第 15 课的修测试演示里，Claude 改完代码后又跑了一遍测试，结论才有证据。
  • 写进 CLAUDE.md：把测试、类型检查、lint 的命令写进项目的 CLAUDE.md，它每次会话都会读到，验证就成了默认动作（第 12 课）。
  • 警惕“看起来修好了”：如果它说“已修复”，却没有运行任何检查，追问一句“你怎么确认的？”
  • API 和库的版本：模型可能记得旧版本的写法。让它查项目里锁定的依赖版本，或者读一下本地的类型定义和文档。

05哪些事不该交给它

判断一件事该交给 Agent 多少，只需要问自己两个问题。这是全书通用的两条标准，后面讲安全的第 9 课也会用到：

  • 出错的代价有多大？改个错别字和转一笔钱，代价天差地别。
  • 结果我能不能轻松核对？一眼能看出好坏的，可以放手；看不出来的，要么自己核对，要么请专业人士。

代价大、又难以核对，或者发出去就收不回的事，比如健康和用药的决定、投资下单、以你的名义对外发消息，应该由你来拍板。Claude 可以帮你整理资料、起草文字，但最后那一下要你自己按。

06动手试一试

🔎 让 Claude 自己标出没把握的地方 不需要写代码

挑一个你很熟悉的话题（你的专业、家乡、爱好），让 Claude 写一段介绍，然后追问：

刚才那段介绍里，哪些说法你最没有把握？请逐条列出来，并说明原因。哪些需要查最新资料才能确认？
  1. 用你自己的知识检查那段介绍，找出至少一处不准确或过时的地方。
  2. 它自己列出的“没把握”的地方，和你找到的错误重合吗？
  3. 打开网页搜索，请它核对那几处，并附上来源。

  1. 看它调用了几次 Read / Grep，有没有“没读就答”的地方。
  2. 随机挑一个它提到的函数，自己打开文件核对。

07常见误区

✗

Claude 语气很确定，说明它很有把握。

✓

语气和准确性没有必然联系。幻觉往往说得和真话一样流畅，判断依据应该是来源和证据。

✗

开了网页搜索，就不会有幻觉了。

✓

搜索能大幅减少过时和编造，但网页本身也可能出错，它也可能误读。重要的事点开来源看一眼。

✗

它知道今天发生的所有事。

✓

模型的知识有截止日期。截止日期之后的事，要靠搜索或者你提供的材料。

✗

既然会出错，那就什么都别交给它。

✓

按代价和可核对程度分配：低风险、好核对的事放手交给它，省下的时间用来把关真正重要的部分。

08小测验

Q1你让 Claude 推荐几本书，它给了一本你搜不到的书。最可能是什么情况？
书名、作者、论文这类“看起来像真的”的具体信息，是幻觉的高发区。B 不太可能：Claude 的知识来自截止日期之前的资料，它不会凭空知道一本刚出版、还没被收录的书；真正的新书一般也能在书店或出版社网站上查到。请它给出版信息或来源链接，再核对。
Q2下面哪个问题最需要 Claude 去搜索，而不是凭记忆回答？
开放时间会变，而且很可能在知识截止日期之后调整过。A 是稳定的知识，C 只需要你给的文字。
Q3哪件事最应该由你自己来拍板？
对外、以你的名义、发出去收不回，代价大。Claude 可以起草，但发布前要你审核并亲自发出。
Q4（开发者）Claude Code 说“已修复”，以下哪种情况最值得追问？
没有验证的“已修复”只是一个判断，不是证据。把“运行测试并全部通过”写进完成标准或 CLAUDE.md。
