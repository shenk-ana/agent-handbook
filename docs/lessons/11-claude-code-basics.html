上手 Claude Code
CLI、桌面端与 IDE

Claude 应用里的 Claude 能聊天、能查资料；Claude Code 则直接坐到你的项目文件夹里：读代码、改文件、跑命令。比如你说“把这个网站的登录页改成深色”，它会自己找到相关文件、改好、跑一遍检查，再告诉你结果。这一课带你装好它、开好第一个会话，并学会看懂它在屏幕上做的每一件事。

⏱ 约 20 分钟 👤 第一节所有人可读；其余以开发者为主 🎬 1 个交互演示 · 1 张图示

学完这一课，你能

  • 说出 Claude Code 的几种形态，以及各自适合什么样的人
  • 在电脑上安装并登录 Claude Code，开始第一个会话
  • 看懂界面上的工具调用、差异（diff）和确认框，知道什么时候按 Esc
  • （开发者）用 /init、/context、/compact、/resume 等命令管理日常会话
  • （开发者）理解用量从哪里来，知道几种省用量的习惯

一句话总结

Claude Code 是在你项目里干活的 Claude：先让它读懂项目、写好 CLAUDE.md，再看着它的每一步工具调用，该放行就放行，该打断就打断。

01Claude Code 是什么，有哪几种形态

在 Claude 应用里，你把文件上传给 Claude，它读完给你建议，改动还得你自己去做。Claude Code 不一样：你在电脑上把它“领进”一个项目文件夹，它自己去翻文件、改代码、运行测试，做完告诉你结果。第 15 课讲的“思考 → 行动 → 观察”循环，在这里每天都在转。

🧩
打个比方：远程顾问和驻场工程师

Claude 应用像一位远程顾问，你把材料发过去，他回一份意见。Claude Code 像一位驻场工程师，坐到你的工位上直接动手。驻场的人能干的事更多，所以你也要多盯着点：哪些柜子能开，哪些操作要先问你。

Claude Code 有好几种“外壳”，背后是同一个引擎。项目里的 CLAUDE.md、设置文件和 MCP 配置在各种形态里通用。第 3 课已经从“产品家族”的角度比较过它们，这里只按“我是谁”来挑：

形态适合谁
终端（在命令行里输入 claude）习惯命令行的人
桌面应用里的 Code不想碰命令行、喜欢点鼠标看改动的人（需要付费订阅）
编辑器插件（VS Code、JetBrains 等）平时就在写代码的软件里工作的人
网页版（claude.ai/code）手边没有项目文件、想把长任务放到云端跑的人

简单说：想在文字界面里用，选终端；想点点鼠标，选桌面应用；平时在写代码的软件里工作，就装那个软件的插件。用熟以后，几种形态可以混着用。

原理层各形态的细节差别▾
  • 终端 CLI：功能最全，新功能通常最先到这里；claude -p 可以写进脚本和 CI。
  • 桌面应用的 Code 标签页：需要 Pro、Max、Ultra、Team 或 Enterprise 订阅；应用自带 Claude Code，不用另装 Node.js 或 CLI。
  • VS Code 插件（也支持 Cursor）：需要 VS Code 1.94 或更新版本。插件自带一份 CLI，只供它的聊天面板使用；想在 VS Code 的集成终端里运行 claude，仍要单独安装 CLI。
  • JetBrains 插件：在 IDE 的终端里运行 claude 并与之连接，不自带 CLI，要先单独装好。
  • 网页版：会话在云端运行，需要连接 GitHub 等代码托管平台才能拉取和推送代码。

以上截至 2026-11，以官方 desktop、vs-code、jetbrains、claude-code-on-the-web 文档为准。

02安装和登录

下面这些操作需要在电脑上进行。手机上的 Claude 应用可以查看和指挥云端会话，但不能在本机安装 Claude Code。

先准备一个账号：最常见的是 Claude 的付费订阅（Pro、Max 等）。

原理层终端 CLI 的安装与登录▾

其他账号（截至 2026-11，以官方快速入门为准）：除了 Pro、Max、Ultra、Team、Enterprise 订阅（官方推荐），还可以用 Claude Console（开发者平台，按 API 用量预付费），或企业的云平台（Amazon Bedrock 等）。

官方推荐用原生安装脚本。打开终端，按系统选一条（以官方快速入门为准）：

curl -fsSL https://claude.ai/install.sh | bash
claude --version   # 打印版本号，说明装好了

irm https://claude.ai/install.ps1 | iex
  • 其他方式：Homebrew（brew install --cask claude-code）、WinGet（winget install Anthropic.ClaudeCode），以及 apt、dnf、apk。原生安装会在后台自动更新，Homebrew 和 WinGet 不会，需要自己定期升级。
  • Windows 用户：官方建议装上 Git for Windows，这样 Claude Code 能使用 Bash 工具；没装时会改用 PowerShell。
  • 登录：进入项目目录运行 claude，第一次会提示登录，在浏览器里完成授权即可，之后不用再登。要换账号，在会话里输入 /login。
  • 装好以后找不到命令：多半是安装目录不在 PATH 里，按官方“Troubleshoot installation”页面处理。

桌面应用：在 macOS 或 Windows 上下载安装 Claude 桌面应用，登录后点侧栏顶部的 Code 标签页，选“Local”环境并打开项目文件夹。VS Code：在扩展视图里搜索“Claude Code”安装。JetBrains：先装好 CLI，再从 JetBrains Marketplace 安装 Claude Code 插件并重启 IDE。

03第一次会话该做什么

装好以后，别急着让它写新功能。第一次会话做三件事就够了：

  1. 确认信任这个文件夹：第一次在某个文件夹里启动时，Claude Code 会弹出工作区信任对话框。只在你自己的、或者确实信得过的项目里选“信任”。
  2. 问它“这个项目是做什么的？”：这是官方快速入门推荐的第一个问题。它会自己翻目录、读说明文件，你正好借机观察它怎么工作。
  3. 输入 /init：让 Claude 分析代码库，生成一份 CLAUDE.md 初稿，记下构建命令、测试命令和项目约定。以后每个会话开始时，它都会先读这份文件。
⚠️
为什么“信任”这一步不能随手点

项目里可以带着 Claude Code 的配置文件，例如自动放行某些命令的规则、会自动运行的脚本。别人的仓库里写了什么，你未必看过。所以 Claude Code 要你先确认信任，这些配置里放宽权限的部分才生效。来路不明的仓库，先在编辑器里看看 .claude/ 目录和 .mcp.json 再决定。第 12 课会细讲。

原理层/init 生成了什么，接下来怎么改▾
  • /init 会写出项目根目录的 CLAUDE.md，内容是它从代码里发现的构建命令、测试方法和约定。如果已经有 CLAUDE.md，它会给出改进建议，而不是覆盖。
  • 把环境变量 CLAUDE_CODE_NEW_INIT 设为 1 再运行 /init，会进入交互式流程：它会问你要配置哪些东西（CLAUDE.md、Skills、Hooks），用子 Agent 探索代码库，追问细节，最后给出一份方案让你审完再写文件。
  • 初稿只是起点。要补上它从代码里看不出来的东西：哪些目录不能动、提交前必须跑什么、团队约定的命名方式。写法和反例见第 12 课。
  • 如果仓库里已经有给其他编程 Agent 用的 AGENTS.md，而没有 CLAUDE.md，新版 Claude Code（v2.1.277 起）会直接读取它。

Claude Code 干活时，屏幕上会不断冒出新的行。看懂它们，你就知道它在想什么、做了什么、要你决定什么。下面这张图是自绘的终端示意，真实界面的细节会随版本变化，以界面为准。

🖐
三个“刹车”键（电脑上）

Esc：打断当前的回答或工具调用，已经做完的部分保留，你可以补一句话把它拉回正轨。输入框为空时连按两次 Esc：打开回退菜单，把对话或代码恢复到之前的某个时间点。Ctrl+C：中断正在运行的操作；什么都没在运行时，第一次清空输入，第二次退出 Claude Code。

还有一个值得常看的指标：上下文占用。会话越长、读的文件越多，Claude 的“办公桌”就越满（第 5 课的比方）。输入 /context，会看到一张彩色格子图，显示系统提示词、工具定义、CLAUDE.md、对话各占了多少。

05常用命令速览

在输入框开头输入 /，会弹出所有可用的斜杠命令和 Skills。最常用的两个：/help 看帮助；/clear 做完一件事、开始另一件时清空对话。其余命令以 /help 和官方命令参考为准。

原理层日常命令速查表（截至 2026-11）▾

/help显示帮助和可用命令忘了命令时
/init分析项目，生成 CLAUDE.md 初稿项目第一次用 Claude Code
/clear开始一个上下文为空的新对话做完一件事，开始不相关的另一件
/compact [重点]把到目前为止的对话总结压缩，腾出空间同一件事还没做完，但上下文快满了

/model切换模型并保存为新会话的默认值复杂任务换更强的模型，简单批量换更快的
/resume按名称或 ID 恢复以前的对话，或打开会话列表接着昨天的活干

原理层在终端外启动：命令行参数与非交互模式▾
在 shell 里输入作用
claude启动交互模式
claude "修一下构建报错"带着第一条指令启动交互模式

claude -p 就是无头模式，也是 Agent SDK 的命令行入口（第 22 课）。它默认使用手动模式（命令行参数里的配置值是 default），需要批准的工具调用没人可问，会被拒绝，所以常配合 --allowedTools 预先放行。-p 不显示信任对话框，风险和对策见第 21 课。

06费用和用量：心里有个大概

Claude Code 每一轮都要把对话历史、读进来的文件、工具结果一起发给模型，按 token 计算用量。token 是 Claude 阅读和书写的“字数单位”，读得越多、写得越多，用量越大（第 16 课详讲）。具体价格和套餐额度会变，这里不写数字，只讲三个概念：

  • 订阅用户（Pro、Max 等）：用量算在套餐额度里，用到上限要等额度恢复。/usage 会显示额度进度条和用量构成。
  • Console（API）用户：按实际 token 计费。/usage 里的金额是本机按标价估算的，以账单为准。
  • 用量随上下文增长：同一个会话越长，每一轮要发送的内容越多。子 Agent 也会单独发请求，同样计入你的额度。

几个省用量、也让 Claude 更清醒的习惯（来自官方成本指南）：

  • 换一件不相关的事就 /clear；长任务中途用 /compact 压缩，可以附上“重点保留什么”。
  • CLAUDE.md 只写每次都要用的约定，长篇流程挪进 Skills（第 7 课），用到时才加载。
  • 不用的 MCP 服务器关掉（第 14 课）；读大量日志、搜大量文件这类活交给子 Agent，主对话只拿回摘要（第 13 课）。
  • 把要求说具体：“修好登录页输错密码后白屏的问题”比“修个 bug”少走很多弯路。

07动手试一试

👀 先看懂演示 不需要写代码
  1. 播放本课的演示，暂停在每个 ⏺ 行，说出它是在“读”还是在“写”。
  2. 找出演示里 Claude 停下来问你的两个地方，想一想：为什么第一个问的是文件夹，第二个问的是文件？
  3. 如果第二个确认框选了“否”，你会告诉 Claude 什么？

参考答案：ls -a 和 Read 是读，Write 是写。第一次问的是“这个文件夹信不信得过”，因为项目里可能带着会放宽权限的配置；第二次问的是“这个文件能不能写”，因为写文件会改变你的项目。选“否”时可以说明想要的改法，例如“先别写文件，把内容贴出来给我看”。

🖥 在自己的项目里开第一个会话 开发者

需要在电脑上操作。挑一个你熟悉、已经提交干净的项目（方便用 git 撤回）。

  1. 进入项目目录运行 claude，完成登录，确认信任文件夹。
  2. 输入：
    这个项目是做什么的？入口在哪里，怎么运行测试？先别改任何东西。
  3. 对照它的回答，检查有没有说错的地方。然后输入 /init，读一遍生成的 CLAUDE.md，补上两条它不知道的约定。
  4. 输入 /context，看看 CLAUDE.md 和刚才读的文件各占了多少；最后用 git diff 确认它只动了 CLAUDE.md。

08常见误区

✗

桌面端、VS Code 和终端是三个不同的 AI，配置要各写一份。

✓

它们是同一个 Claude Code 引擎的不同外壳，在同一台电脑上读的是同一套设置文件和 CLAUDE.md。

✗

信任对话框点“是”就是走个过场。

✓

信任以后，仓库里放宽权限的配置才会生效。对陌生仓库，先看过 .claude/ 和 .mcp.json 再信任。

✗

它跑起来就只能等它跑完。

✓

随时可以按 Esc 打断、补充指令；改歪了可以用 /rewind 回退。

✗

一个会话从早用到晚最省事。

✓

会话越长，每轮发送的内容越多，早期细节也越容易被挤模糊。一件事一个会话，换事就 /clear。

09小测验

Q1你平时只用编辑器，从不开终端，想最省事地开始用 Claude Code，比较合适的是？
各形态背后是同一个引擎，按习惯选就行。编辑器插件让你不离开熟悉的软件就能用上它；不想碰命令行的话，桌面应用里的 Code 也是一个选择。
Q2Claude Code 正在执行一串你没想到的操作，你想让它马上停下来、换个方向，应该？
Esc 会停下当前的回答或工具调用，已完成的工作保留，你可以立刻纠正方向。
Q3（开发者）同一个会话里，前一个任务已经做完，你要开始一个和刚才无关的新任务。最合适的命令是？
/clear 开一个上下文为空的新对话；/compact 适合同一件事还要继续、只是需要腾空间；/init 是生成 CLAUDE.md 的。
Q4（开发者）界面上出现一行缩进的 ⎿ Tests: 1 failed，它是什么？
⏺ 开头的是工具调用（行动），下面缩进的 ⎿ 是工具结果（观察）。
