Model / 模型

理解与生成内容的核心能力。换模型，会影响能力、速度和使用量。

Agent / 代理

围绕目标使用模型和工具，多步执行、观察结果并调整的工作者。

Prompt / 提示词

本次任务的要求。写清目标、材料、限制和交付格式，比堆术语有用。

Context / 上下文

这次能参考的对话、文件和工具结果；不是电脑里所有文件，也不是永久记忆。

Skill / 技能

针对某类任务的流程与资源。把做事方法存成一份可重复使用的说明。下次换一份材料，AI 仍可按这套方法做。

Plugin / 插件

方便安装和共享的能力包，可包含 Skill、MCP 等。只有说明的技能不一定需要联网。

再认识几个常见词：Tool、Token、API、项目规则

Tool：具体可执行的动作，例如搜索、读取文件。MCP server：提供这些能力的服务；连接后仍受权限约束。Token：模型处理文本等内容时使用的计量单位，不等于汉字数。API：让程序调用服务的接口，初学者使用产品界面通常不需要自己编程调用。项目规则：告诉 AI 这个项目长期要遵守什么；具体文件可让 AI 帮你创建。代码仓库：保存项目与版本历史的地方。沙箱：限制执行和访问范围的环境。

概念依据：Skills & Plugins。这些能力不是每次都需要：粘贴一段文字并让 AI 整理，也是一种完整用法。

02 / CHOOSE YOUR WORKSPACE

Work 与 Codex：
能力重叠，工作视角不同。

想完成一项任务，可以直接从 Work 开始。Codex 更适合需要查看代码改动和开发细节的工作；Chat 则适合问答与来回讨论。它们是工作入口，不是模型等级。

WORK / 以交付成果为中心

“请把这件事做好。”

你主要关心最后得到什么：报告、表格、演示稿、整理好的文件，或者一个能使用的页面。界面倾向展示进度与成品，少呈现开发细节。

  • 适合：给材料、定要求、检查成品、继续修改。
  • 也能：在能力与权限允许时写代码、运行工具、处理技术任务。
  • 新手起点：直接给目标；不必先学代码仓库和开发操作。
CODEX / 以开发过程为中心

“在这个项目里修改并验证。”

你除了要结果，还关心文件怎么改、改动前后有什么不同、测试是否通过，以及如何与代码版本协作。界面更强调项目和开发审查。

  • 适合：修复程序、实现功能、检查代码差异与测试。
  • 也能：研究、写文档、做演示稿和其他知识工作。
  • 已熟悉 Codex：可以继续用它做办公任务，不必为了名称换工具。
不是能力高低的分级。Work 不是“简化版弱模型”，Codex 也不是“只有程序员才能用”。选择主要看你想怎样管理和查看工作；实际能做什么，还取决于模型、工具、运行环境与权限。官方明确说明二者核心能力重叠，但呈现方式不同。

官方：Work 与 Codex 的界面、技术细节和工作方式对照 ↗

同一类需求Work 的起步方式更适合切到 Codex 的情况
做一个网页“做一个报名页面，手机也能用，完成后给我预览。”已有网站项目，需要精确改文件、审查差异并运行测试。
处理一张表格“整理这张销售表，找出异常，交付汇总报告。”要将处理逻辑做成长期维护的程序，并管理代码版本。

既然 Work 能做事，为什么还保留 Chat？

只想问一个问题、解释术语、改一句话或来回讨论时，Chat 已足够。较复杂的 Work 任务可能花更多时间和使用量；它并不是每个短问题都更划算。但你完全可以直接在 Work 中先讨论，再执行，无需先经过 Chat。

本教程的建议：想委派任务时，优先 Work；想查看代码项目与开发审查细节时，优先 Codex；只想问答时，Chat 即可。原来的 Chat → Work 案例保留为可选练习，不再当成必经步骤。

WORK 与本地目录 / 材料在哪，成果放哪

长期做文件任务，指定独立目录通常更好。

这样更容易反复读取同一批材料、把成果保存到固定位置，也便于你找到和检查文件。只是问答、粘贴文字或使用已上传文件时，不必先创建本地目录。

  1. 在电脑上建一个只用于本任务的文件夹，例如“AI会议练习”；也可以先请 Agent 帮你创建，并说明保存位置。
  2. 在支持本地访问的桌面应用中，选择本地项目并添加这个文件夹。已有本地项目可在项目菜单的 Edit project（编辑项目）→ Add folder（添加文件夹）中调整；以实际界面为准。
  3. 让 Agent 建立“资料”和“成果”两个子文件夹，把要处理的材料放在资料中，说明成果保存到哪里。
  4. 先让 Agent 说明当前能访问哪些文件，再处理一份练习材料。完成后实际打开成果核对。

目录不是越大越好。优先添加本任务的文件夹，材料和输出边界更清楚。一个项目中的文件夹也不等于技能的安装位置；保存技能时仍需确认作用范围和可用状态。
网页里的“项目”，是否等于电脑上的文件夹？

不等于。普通 ChatGPT 项目组织聊天、上传文件和共享说明，不会因此直接读到电脑文件夹。只有具备本地访问能力、选中了相应本地项目 / 文件夹并获得权限，才可以处理其中的文件。仅在聊天里打出文件夹名字，也不算完成连接。

Work 云端、本地、指定目录，怎样理解？

云端工作使用云端可访问的材料和工具，例如上传文件或已连接的应用；本地工作可使用获准访问的电脑文件与应用。支持“云端协调 + 本地电脑访问”的账户也可能两者结合，所以不能单凭 Cloud 字样判断能否读本地文件，应核对这次任务实际可用的资源。

需要电脑文件的步骤通常要求电脑在线、相应应用和连接可用。指定本地目录不代表离线推理，也不表示内容永远不经过云服务；它主要解决材料访问与工作范围的问题。

依据：项目与本地文件夹 · Work 执行位置 · 本地访问与数据处理说明。界面及本地访问能力受设备、账户和工作区配置影响。

Skill，就是给 AI
保存一份“做事说明书”。

比如每次整理会议记录，你都要求“分三列、不要猜、缺失写未说明”。把这些固定要求保存成技能，以后只需要告诉它这次要处理哪份记录。

怎么知道是真的保存了，而不是只写了一段说明？

检查三个信号：能在技能或插件界面找到它；已按提示完成安装或启用；新建对话后可以选择它，并用新材料得到符合规则的结果。只有聊天中出现“已保存”几个字，还不够。

Chat、Work、Codex 分别怎样做？

Chat / Work：先用自然语言说明要保存什么。在支持的界面中，通过输入框的选择菜单找到 Plugin Creator（插件创建器），把要求交给它；按提示完成创建、安装和测试。输入框中的 @ 是打开选择菜单的界面入口，无需学习编程命令。

Codex：直接说“请把刚才的工作流程做成技能，帮我保存好并告诉我如何复用”。让 Agent 确认是只供自己使用，还是供整个项目使用，并完成所需文件与设置；你无需手写技能文件。

创建器或保存功能不可用时，先让 AI 把做法整理成可复制的提示模板。模板可以手动复用，但应明确它还不是已安装的技能。

什么值得变成技能，什么暂时不用？

每周都会做、规则相对稳定、经常重复纠正的工作值得保存，例如会议整理、固定格式周报、按清单审查网页。一次性的闲聊、尚未做对的流程，或只与某一份材料有关的内容，可以先留在当前对话里。

以后想修改这个技能怎么办？

选择有编辑权限的创建器并说：“请更新我已有的『会议行动清单』技能，不要新建重复版本。新增规则：如果负责人不明确，单独列出待确认问题。完成后用一份新记录测试。”检查更新后的说明，并按产品提示重新开始对话或刷新使用。

自然语言能表达目标，但不能代替必要的账户权限、安装或人工授权；以创建器和界面实际返回的结果为准。完整步骤见下方实战。

可以说：“请用本教程的虚构材料和默认格式先完成最小示例；只问阻止你继续的必要问题。未知负责人或日期写未说明。”账户登录、授权或付费等选择仍由你自己决定。

它生成了结果，我怎样保存下来？

本例的结果就是对话里的表格，可以复制到自己的笔记或文档。如果需要文件，直接说“请把这张表保存成可下载的文档，并给我打开入口”。只有实际出现文件或可打开链接才算文件已生成；没有文件能力时先复制表格。

AI 说自己看不到我正在用的页面。

告诉它应用名称、你所在页面和看到的按钮文字。需要截图时，先遮去姓名、邮箱等个人信息。不要假设所有 Agent 都能控制你的电脑；它可能只能给你操作指引。

显示额度不足、功能不可用或需要升级。

先查看产品给出的说明。可以保留材料和模板，换到已能使用的工具完成文本练习；不要为了跟完教程盲目付费。安装成功、功能权限和剩余额度是三件不同的事。

需要连接外部资料时，怎样用自然语言让 Agent 帮忙？

先说：“我想让你读取我网盘里的会议记录并整理。请检查需要哪个插件；能替我设置的请帮我做，需要我登录或授权的请告诉我点哪里。”按提示到插件目录安装，连接自己的账户并检查授权范围。没有连接成功之前，不要假设 AI 能看到网盘内容。

如确实需要自定义 MCP，可以说：“请帮我接入这个可信服务，并说明需要我在界面中填写或确认什么。完成后用一次只读查询验证。”服务地址与认证信息应来自服务方；自然语言不会绕过账户权限。

想让多个 Agent 分工，应该怎么说？

可以直接说：“请把资料检查与表格整理分给不同子代理，最后由你核对并汇总；如果当前环境不支持，就依次完成。”让主代理报告实际委派情况。我们的会议练习很简单，无需特意使用多代理。
